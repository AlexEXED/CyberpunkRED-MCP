# 神谕引擎（Oracle Engine）

> 单人跑团（Solo Play）的 GM 替代机制。用"带概率分布的随机判定"取代 GM 的主观判断。
> **本目录只含机制设计与重建指南，不含任何版权随机表数据。**

---

## 一、这是什么

单人跑团的核心难题：**没有 GM 时，谁来回答"接下来发生什么"？**

传统方案让 AI 自由编故事，会产生两个问题：
1. **一致性崩塌** —— 同一套规则，每次结果都不同
2. **倾向性漂移** —— AI 倾向"顺着玩家"或"制造戏剧性"

神谕引擎的解法：**把不确定性交给引擎，把确定性交给规则。**

```
AI 决定"掷什么骰"  →  骰子决定"发生了什么"  →  AI 只负责把结果讲成故事
```

## 二、核心机制

### 2.1 五级概率判定

GM 不再回答"是/否"，而是先评估概率等级，再由骰子裁决。

| 等级 | 含义 |
|------|------|
| `必然` | 几乎一定发生 |
| `很可能` | 大概率发生 |
| `50/50` | 五五开 |
| `不太可能` | 小概率发生 |
| `不可能` | 几乎不会发生 |

### 2.2 五结果区间（非二元）

每个概率等级映射到 d100 的五个区间：

| 结果 | 含义 |
|------|------|
| `否` | 否定，直接叙事 |
| `否但` | 否定，但有转折/补偿 |
| `复杂化` | 结果复杂，产生新变数 |
| `是但` | 肯定，但附代价/并发症 |
| `是` | 肯定，直接叙事 |

**为什么五档而非二档？** 二元"是/否"会杀死叙事张力。"否但"/"是但"给了转折钩子——事情不是简单成败，而是"成功但有代价"。

### 2.3 极端反转（O-15）

当"必然"档掷出否定、或"不可能"档掷出肯定时，触发**极端反转**——GM 预期被彻底颠覆，需触发强者时钟吸收戏剧张力。

### 2.4 强者时钟（压力系统）

- 6d6 骰池代表局势稳定度
- 每次极端反转掷骰，掷出 1 的骰子被移除
- 骰池归零 = 局势崩溃

```
6d6 → 稳定 → 掷出1移除 → 4d6 → 恶化 → ... → 0 → 崩溃
```

### 2.5 偏移系统（O-16）

GM 想修正随机结果，必须付出等量代价：

```
原始结果 index=89，GM 想要 index=14
偏移量 = |89-14| = 75 → 封顶 5 → 注入 5 级麻烦
```

防止 GM/AI 随意"改顺"故事，保证戏剧张力守恒。

### 2.6 开放式神谕三表（O-08）

开放式问题（"我发现了什么？"）用三张百词表组合：

| 表 | 角色 |
|----|------|
| 动词 | 行动锚定 |
| 名词 | 对象锚定 |
| 形容词 | 特征锚定 |

## 四、如何重建你自己的表格

如果你持有《单人游玩模式》PDF，可按以下方法自行提取、结构化。

### 4.1 数据结构规范

```json
{
  "oracle": {
    "必然": {"否": [1,5], "否但": [6,10], "复杂化": [11,15], "是但": [16,40], "是": [41,100]}
  },
  "morale": [
    ["赛博精神病/死士", [1,2], [3,10]]
  ],
  "tables": {
    "动词": {
      "dice": "1d100",
      "rows": [{"min": 1, "max": 1, "text": "警戒"}]
    }
  }
}
```

### 4.2 提取方法

1. 用 `pdfplumber` 提取 PDF 文本（随机表集中在"清单与表格"章节）
2. 识别表头（格式：`骰子表达式 + 表名`）
3. 解析数据行（格式：`范围 + 内容`）
4. 注意 PDF 的**双列排版**——左右两列交错提取是常见坑，需按列序重组
5. 校验：每张表行序连续无 gap，覆盖完整骰值范围

### 4.3 参考脚本

本项目的数据提取/修复脚本（含完整的数据校验逻辑，可参考改写）：

- `scripts/fix_tables.py` — 修复表数据
- `scripts/add_tables.py` — 新增表数据
- `scripts/fix_tables2.py` — 补齐不完整表
- `scripts/build_table_index.py` — 生成表索引
