# 神谕引擎（Oracle Engine）— 单人跑团随机表体系设计规范

> 单人跑团（Solo Play）的 GM 替代机制：用"带概率分布的随机判定"取代 GM 的主观判断。
> **本文是设计规范 + 范围框架，不包含任何具体数据内容。** 你可以据此自建、自定义、拓展你自己的表格。

---

## 一、核心思想

单人跑团的核心难题：**没有 GM 时，谁来回答"接下来发生什么"？**

```
AI 决定"掷什么骰"  →  骰子决定"发生了什么"  →  AI 只负责把结果讲成故事
```

一个完整的随机表体系，本质是把 GM 的判断职能拆成**可结构化、可复用、可定制**的表格。

---

## 二、数据格式规范

所有表遵循统一的 JSON 结构，这是体系可复用、可拓展的基础。

### 2.1 标准表

```json
{
  "tables": {
    "表名": {
      "dice": "1d100",
      "rows": [
        {"min": 1, "max": 5, "text": "条目内容"},
        {"min": 6, "max": 10, "text": "条目内容"}
      ]
    }
  }
}
```

**字段约定**：
- `dice`：骰子表达式，常用 `1d100`（精细）、`2d6`（高斯分布）、`1d10`（快速）、`2d10`（扩展区间）
- `rows`：行数组，`min`/`max` 是命中区间，`text` 是结果内容
- **行序冻结**：表一旦定稿，行序锁定，便于外部通过 `result_index` 做偏移量引用

### 2.2 神谕（封闭式判定）

```json
{
  "oracle": {
    "必然":   {"否": [1,5],  "否但": [6,10],  "复杂化": [11,15], "是但": [16,40], "是": [41,100]},
    "很可能":  {"否": [1,15], "否但": [16,25], "复杂化": [26,35], "是但": [36,55], "是": [56,100]},
    "50/50":  {"否": [1,20], "否但": [21,30], "复杂化": [31,40], "是但": [41,60], "是": [61,100]},
    "不太可能": {"否": [1,40], "否但": [41,55], "复杂化": [56,65], "是但": [66,75], "是": [76,100]},
    "不可能":  {"否": [1,75], "否但": [76,85], "复杂化": [86,90], "是但": [91,95], "是": [96,100]}
  }
}
```

**设计要点**：
- 五级概率 × 五结果（否/否但/复杂化/是但/是），非二元，保住叙事张力
- 区间宽度随概率等级**平滑移动**，"复杂化"始终占约 10%，保证故事总有意外
- 首尾两档留 5% 的**极端反转**区（必然→否、不可能→是），触发时钟

### 2.3 士气（战斗状态判定）

```json
{
  "morale": [
    ["精神状态", [逃跑区间], [继续战斗区间]]
  ]
}
```

精神状态按"战斗意志"从高到低排列，逃跑倾向呈梯度递增。

## 三、随机表体系的范围框架

一个完整的单人跑团表体系，应覆盖 **8 个维度**。这是"自建表格需要覆盖的范围"——不是死规定，是覆盖建议，可按你的场景裁剪或拓展。

| # | 维度 | 作用 | 建议的表 |
|---|------|------|---------|
| 1 | **神谕判定** | GM 替代，回答是非/开放式问题 | 封闭式神谕、动词/名词/形容词（开放式三表） |
| 2 | **感官氛围** | 场景描写，注入细节 | 光景、声音、气味 |
| 3 | **空间地点** | 场景选址 | 区域、地点类型、住所类型 |
| 4 | **人物关系** | NPC 生成 | 关系、访客、情绪、职业、名称、代号 |
| 5 | **派系组织** | 势力背景 | 派系类型、各派系名录 |
| 6 | **任务剧情** | 剧本生成 | 任务类型、引子、悬崖、开发、高潮、判定、转折 |
| 7 | **物品装备** | 战利品与资源 | 尸体物品、装备、奇物、消耗品 |
| 8 | **战斗辅助** | 结算 | 士气（敌人状态）、时钟（压力骰池） |

### 范围框架的使用方式

- **自建**：按 8 个维度，为你的世界观填充具体表（奇幻 → 派系变公会/教会；科幻 → 地点变空间站/星球）
- **裁剪**：只跑战斗、不跑社交？可去掉"人物关系"维度
- **拓展**：你的场景有独特需求（如"灵异调查"），在框架上**新增维度**即可

## 四、自定义与拓展

### 4.1 自定义表

- 修改任意表的 `dice` 和 `rows`，只要遵守 §2 的格式规范
- 表名自由命名，`roll_table` 按表名做模糊匹配

### 4.2 拓展表范围

- 新增维度：直接在 `tables` 下加新表，无需改代码
- 新增骰种：如 `1d6`、`3d6`，格式规范通用

### 4.3 偏移修正（可选进阶）

若你的引擎需要"GM 修正随机结果"的能力，可引入**偏移系统**：
- 记录每次掷骰的 `result_index`（命中行序号）
- GM 想改成另一结果时，计算 `|目标index - 当前index|`
- 偏移量越大，需要注入越多"叙事麻烦"来平衡（张力守恒）
