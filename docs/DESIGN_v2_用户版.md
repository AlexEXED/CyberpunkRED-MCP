# 扩展系统设计说明（用户版）

> **日期**: 2026-05-07 | **配套技术文档**: DESIGN_v2.md
> **读者**: GM、玩家、非技术人员

---

## 这份文档讲什么？

MCP Server 即将升级"扩展系统"——让你能把第三方规则书（比如 2070 手册、社区房规）导入 AI 跑团引擎，同时保证核心规则书永远不会被破坏。

这份文档用大白话解释这套系统的设计逻辑。

---

## 一、核心理念：三层规则，各司其职

想象你的规则像三层蛋糕：

```
🔝  GM 微调（你说了算）
     "爆头伤害我定 x3"
     ─────────────────
🔶  第三方扩展（可装可卸）
     "2070手册的新武器"
     ─────────────────
🔵  核心规则书（永远不动）
     "官方原版规则"
```

**规则**：
- 上层优先于下层。GM 说了算 > 第三方扩展 > 核心规则书
- 核心规则书永远不会被修改或删除
- 第三方扩展可以随时安装、关闭、卸载
- GM 微调是最终解释权

---

## 二、扩展能做三件事

当你导入一个第三方扩展（比如 2070 手册），里面的每条规则都必须声明自己要做什么：

### 1. 新增（Add）—— 最常见

> "核心规则书里没有等离子步枪，我加一个"

- 搜索"等离子步枪"时会找到这条新规则
- 和核心规则互不干扰

### 2. 替代（Replace）—— 慎用

> "2070 版本的重型手枪伤害改为 4d6，替换原来的 3d6"

- 搜索"重型手枪"时，只返回 2070 版本
- 核心版本被"遮住"但**没有被删除**
- 卸载 2070 手册后，核心版本自动恢复

### 3. 补充（Extend）—— 给老规则加新料

> "重型手枪新增穿甲属性，但保留原来的所有数据"

- 搜索"重型手枪"时，返回两条：核心版本 + 补充内容
- AI 会把两条信息合并理解

---

## 三、GM 微调：你说了算

GM 可以对任何规则做个性化裁定，不管它来自核心规则书还是第三方扩展。

**例子**：
- 2070 手册说重型手枪伤害 4d6
- GM 觉得太强，改成 5d6 → 写一条 GM 微调
- 搜索时返回 GM 的版本（5d6），2070 和核心的都被压下去

**智能休眠**：
- GM 微调可以标注"我这条是针对 2070 手册的"
- 如果 2070 手册被关闭或卸载，这条微调自动休眠
- 2070 手册重新启用时，微调自动恢复
- 不需要手动管理

---

## 四、安装和卸载

### 安装扩展

1. 提供原始文件（PDF / Word / Excel / Markdown）
2. AI 帮你提取内容、分类、映射字段
3. 你审核确认
4. 一键导入

### 关闭扩展（临时）

> "今天跑团不用 2070 规则"

- 扩展被关闭，搜索时不会出现
- 数据还在，随时重新开启

### 卸载扩展（永久）

> "这个扩展我不要了"

- 扩展文件被删除
- 依赖它的 GM 微调进入休眠（不会丢失）

### 不可卸载的

- **核心规则书**：永远在，不能关，不能删
- **GM 微调层**：永远在，不能关，不能删（但可以编辑里面的具体条目）

---

## 五、搜索规则时会发生什么

当你（或 AI）搜索一条规则时，系统会：

1. 搜索所有层（GM 微调 → 第三方扩展 → 核心规则）
2. 跳过已关闭的扩展
3. 跳过休眠的 GM 微调
4. 处理替代关系（Replace 的会遮住核心版本）
5. 按优先级排序返回结果
6. 每条结果都标注来源（"来自核心规则书" / "来自 2070 手册" / "GM 微调"）

你始终能看清每条规则来自哪里。

---

## 六、分类规则

所有规则（不管来自哪一层）都必须归入 7 个标准分类之一：

| 分类 | 内容 |
|------|------|
| injuries | 伤势、重伤、致命伤 |
| combat | 战斗动作、攻击、DV 值 |
| vehicles | 载具 |
| netrunner | 网络、程序、黑冰 |
| skills | 技能 |
| services | 服务、住房、药物 |
| equipment | 武器、护甲、装备、赛博组件 |

如果扩展内容不完全匹配某个分类，选最接近的，在备注里说明实际形态。

---

## 七、安全保证

| 你担心的 | 系统保证 |
|---------|---------|
| 导入扩展会改坏核心规则？ | 不会。核心文件永远不被修改 |
| 卸载扩展后核心规则不完整？ | 不会。核心数据独立存放，卸载只删扩展文件 |
| GM 微调在切换扩展后丢失？ | 不会。微调自动休眠，恢复扩展后自动生效 |
| 搞不清规则来自哪里？ | 每条搜索结果都标注来源层级和具体来源名 |
| 装太多扩展搜索变慢？ | 不会。数据量极小，全量搜索也是瞬间完成 |

---

## 八、一句话总结

**核心规则是骨架，扩展是肌肉，GM 的话是神经。骨架不能被替换，肌肉可以换，神经说了算。**
