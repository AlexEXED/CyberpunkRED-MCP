## 一、设计哲学

单人跑团（Solo Play）的核心难题只有一个：**没有 GM 时，谁来回答"接下来发生什么"？**

传统方案让 AI 直接发挥想象力编故事，但纯自由叙事会产生两个问题：

1. **一致性崩塌** —— 同一套规则，AI 每次给出的结果都不同，无法复现
2. **倾向性漂移** —— AI 天然倾向于"顺着玩家"或"制造戏剧性"，偏离概率应有的分布

我的解法是**把不确定性交给引擎，把确定性交给规则**：

```
确定性（有规则可依）  →  规则库（486 条）   →  search_rules 查询
不确定性（需 GM 判断） →  神谕引擎 + 随机表  →  roll_table 掷骰
叙事缝合（AI 自由发挥） →  只负责"解释结果"    →  不负责"决定结果"
```

**核心原则：AI 决定"掷什么骰"，骰子决定"发生了什么"，AI 只负责把骰子的结果讲成故事。**

## 二、神谕引擎（Oracle Engine）

神谕是单人跑团的 **GM 替代品**。它把"GM 的主观判断"转化为"带概率分布的随机判定"。

### 2.1 五级概率判定

GM 不再回答"是/否"，而是先评估"这件事有多大可能发生"，然后由骰子裁决。

| 概率等级 | 含义 | 典型场景 |
|---------|------|---------|
| `必然` | 几乎一定发生 | "仓库有安保轮班" |
| `很可能` | 大概率发生 | "帮派成员会反击" |
| `50/50` | 五五开 | "路人是敌是友" |
| `不太可能` | 小概率发生 | "这个穷光蛋其实是富二代" |
| `不可能` | 几乎不会发生 | "天上掉下军用原型机" |

### 2.2 五结果区间（非二元）

每个概率等级不只有"是/否"，而是**五个结果**，这是本引擎区别于传统"是/否神谕"的关键：

| 结果 | 含义 |
|------|------|
| `否` | 否定，直接叙事 |
| `否但` | 否定，但有一个转折/补偿 |
| `复杂化` | 结果复杂，局势产生新的变数 |
| `是但` | 肯定，但附带代价/并发症 |
| `是` | 肯定，直接叙事 |

**为什么是五档而不是三档？** 二元（是/否）会杀死叙事张力。"否但"和"是但"给了 AI 一个"转折钩子"——事情不是简单的成功或失败，而是"成功了但付出了代价"，这正是赛博朋克叙事的核心质感。

### 2.3 d100 映射表

每个概率等级映射到 d100 的五个区间。区间宽度随概率等级**平滑移动**，保证"必然"档出"否"的概率极低（5%），"不可能"档出"是"的概率极低（5%）。

| 等级 | 否 | 否但 | 复杂化 | 是但 | 是 |
|------|:---:|:---:|:---:|:---:|:---:|
| `必然` | 1-5 | 6-10 | 11-15 | 16-40 | 41-100 |
| `很可能` | 1-15 | 16-25 | 26-35 | 36-55 | 56-100 |
| `50/50` | 1-20 | 21-30 | 31-40 | 41-60 | 61-100 |
| `不太可能` | 1-40 | 41-55 | 56-65 | 66-75 | 76-100 |
| `不可能` | 1-75 | 76-85 | 86-90 | 91-95 | 96-100 |

**设计特征**：
- "复杂化"区间在所有等级都占约 10% —— 保证故事总有意外
- "必然"档的"是但"区间（16-40，25%）比"是"（41-100，60%）大，鼓励"成功但有代价"
- "不可能"档的 96-100 是**极端反转**区（见 2.5）

### 2.4 非二元结果的后续处理（O-08）

当神谕返回 `否但` / `是但` / `复杂化` 时，不能停在这里。需要**锚定"转折是什么"**：

- 单一转折 → 按场景类型查 1 张随机表（如社交场景 → 情绪表）
- 复杂转折 → 查"开放式神谕三表"（动词 + 名词 + 形容词）组合

```
神谕出"是但" → 查"情绪"表 → "悲怆"
→ AI 缝合："NPC 配合了，但神情悲怆——他正在失去什么。"
```

### 2.5 极端反转（O-15）

当"必然"档掷出 1-5（否）、或"不可能"档掷出 96-100（是）时，触发**极端反转**。

这不是普通的"结果意外"，而是**剧情层面的重大变故**：GM 的预期被彻底颠覆，必须触发强者时钟（见第四节）来吸收这个戏剧张力。

## 三、开放式神谕三表（O-08 核心工具）

当问题无法用"是/否"回答时（开放式问题，如"我发现了什么？"），用三张百词表组合生成。

| 表 | 骰子 | 条目 | 角色 |
|----|:----:|:----:|------|
| `动词` | 1d100 | 100 | **行动锚定** — 发生了什么动作 |
| `名词` | 1d100 | 100 | **对象锚定** — 动作作用的对象 |
| `形容词` | 1d100 | 100 | **特征锚定** — 对象的修饰特征 |

三表组合示例：

```
动词="突破" + 名词="防火墙" + 形容词="锈蚀的"
→ "你突破了锈蚀的防火墙"
```

这三张表构成了开放式神谕的**最小完备集**：任何"发现了什么 / 遭遇了什么 / 这里有什么"都能通过"动作 + 对象 + 特征"的三元组锚定，AI 只负责把这三个词织成句子。

## 四、强者时钟（Dice Pool 压力系统）

神谕解决"发生了什么"，时钟解决"什么时候崩"。

### 4.1 机制

- 一个 **6d6 骰池** 代表当前局势的稳定度
- 每次极端反转 / 事实矛盾触发时钟判定：掷全部骰子
- 掷出结果为 **1 的骰子被移除**，骰池缩小
- 骰池归零 = **局势彻底崩溃**，剧情进入高潮或失败分支

### 4.2 设计意图

```
6d6 全池  →  局势稳定，容错高
  │  掷出 1 移除
  ▼
4d6       →  局势恶化，压力上升
  │
  ▼
2d6       →  濒临崩溃
  │
  ▼
0         →  崩溃（高潮/失败）
```

骰池的物理衰减**可视化**了压力——AI 和玩家都能直观看到"还有多少余地"。这是一个从"抽象紧张"到"可计数的紧张"的转化。

## 五、士气系统

战斗场景的 NPC 行为判定。GM 不再主观决定"敌人跑不跑"，而是按敌人的精神状态等级掷骰。

| 精神状态 | 逃跑 | 继续战斗 |
|---------|:---:|:---:|
| 赛博精神病/死士 | 1-2 | 3-10 |
| 资深战士/中尉 | 1-4 | 5-10 |
| 训练有素 | 1-6 | 7-10 |
| 新手/炮灰 | 1-8 | 9-10 |
| 怯懦/杂兵 | 1-9 | 10 |

**设计特征**：精神状态的"逃跑倾向"呈梯度——从死士（几乎不跑）到杂兵（几乎必跑）。这保证了 NPC 的逃跑行为**符合其身份设定**，而不是随机乱跑。

## 六、偏移系统（O-16）

GM 想修正随机结果时，不能白改——**修正必须付出代价**。

### 6.1 机制

```
原始结果：roll_table("关系") → "敌对者" (index=89)
GM 想要：  "挚友" (index=14)

偏移量 = |14 - 89| = 75 → 封顶 5 → 5 级麻烦
```

### 6.2 代价注入

偏移量越大，GM 需要注入越多"麻烦"来平衡：
- 1 级：额外前置任务
- 3 级：NPC 反水风险 + 时间压力
- 5 级：多线危机并发

**设计意图**：防止 GM（或 AI）随意改骰子把故事改"顺"。想改结果可以，但要付出等量的叙事代价，保证戏剧张力守恒。

## 七、随机表分类体系（39 张）

39 张表按**叙事需求**分为 7 大类，覆盖单人跑团从场景到人物的全部生成需求。

| 类别 | 表数 | 表名 | 用途 |
|------|:----:|------|------|
| **开放式神谕** | 3 | 动词 / 名词 / 形容词 | O-08 非二元结果锚定 |
| **感官与环境** | 3 | 光景 / 声音 / 气味 | 场景氛围 |
| **空间与地点** | 6 | 区域 / 地点类型 / 4 种住所描述 | 场景选址 |
| **人物与关系** | 10 | 人物类型 / 人员类型 / 访客 / 关系 / 名称 / 操控名 / 情绪 / 职业 / 时尚类型 / 时尚装置 | NPC 生成 |
| **派系与组织** | 3 | 企业名录 / 帮派笔记 / 帮派类别 | 势力背景 |
| **任务与剧情** | 8 | 任务类型 / 引子 / 悬崖时刻 / 开发 / 高潮 / 判定 / 剧情转折 / 事件 | 剧本生成 |
| **物品与装备** | 6 | 件物品 / 物品 / 奇物 / 火器类型 / 黑冰类型 | 战利品与装备 |

### 设计特征

1. **按叙事阶段组织**：从"场景氛围"到"人物"到"剧情推进"到"战利品"，覆盖一个跑团回合的完整生成链路
2. **多骰种混合**：1d100（精细）/ 2d6（高斯分布，住所类）/ 1d10（快速）/ 2d10（扩展区间）
3. **行序冻结**：表一旦定稿，行序锁定，偏移量引用（O-16）绑定 `version + row_index`

## 八、子系统与 GM 路由节点的关系

神谕引擎和随机表是整个"GM 路由节点"体系的一部分：

```
叙事层（AI 自由）→ 路由层（AI 选节点）→ 结算层（锁死）
                         │
         ┌───────────────┼───────────────┐
         ▼               ▼               ▼
      N8 神谕判定    N9 遭遇生成      N10 时钟推进
      （是/否问题）   （开放式问题）   （压力管理）
         │               │               │
         ▼               ▼               ▼
      roll_table      roll_table       roll(Nd6)
      ("神谕 XX")     ("动词/名词/...")  骰池衰减
```

三个节点对应三种 GM 职能，全部由确定性工具支撑，AI 只负责选择走哪个节点。

## 九、工程实现

### 9.1 数据结构

```json
{
  "oracle": {
    "必然": {"否": [1,5], "否但": [6,10], "复杂化": [11,15], "是但": [16,40], "是": [41,100]},
    "50/50": {"否": [1,20], "否但": [21,30], "复杂化": [31,40], "是但": [41,60], "是": [61,100]}
  },
  "morale": [
    ["赛博精神病/死士", [1,2], [3,10]],
    ["怯懦/杂兵", [1,9], [10,10]]
  ],
  "tables": {
    "动词": {"dice": "1d100", "rows": [{"min":1, "max":1, "text":"警戒"}, ...]}
  }
}
```

### 9.2 MCP 工具接口

| 调用 | 用途 |
|------|------|
| `roll_table("神谕 50/50")` | 五级概率判定 |
| `roll_table("神谕 必然", roll_value=3)` | 极端反转检测 |
| `roll_table("动词")` | 开放式神谕锚定 |
| `roll_table("士气")` | NPC 士气判定 |
| `roll("6d6")` | 强者时钟骰池 |
| `roll("1d10+7")` | 技能判定 |

### 9.3 关键技术决策

| 决策 | 结论 |
|------|------|
| 骰子统一 | 全部用 d100 / d10 / d6 标准骰，无自定义骰种 |
| 行序冻结 | 表行序锁定，偏移量引用绑定版本号 |
| 数据只读 | 引擎数据层只读，AI 消费端无法篡改结果 |
| 来源标注 | 每条规则/表带来源身份证，可追溯 |

## 十、这套架构解决了什么

| 问题 | 传统 AI 方案 | 本架构 |
|------|-------------|--------|
| 结果不一致 | AI 自由发挥，每次不同 | 骰子决定，可复现 |
| 倾向性漂移 | AI 顺着玩家 | 概率分布固定 |
| 叙事平淡 | 二元"是/否" | 五档结果 + 转折钩子 |
| GM 随意改骰 | 想改就改 | 偏移系统强制代价 |
| 压力无感 | 抽象紧张 | 骰池可视衰减 |
