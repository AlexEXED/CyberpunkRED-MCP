# AI 协作铁律：从血泪教训到系统性防御

> 来源：CPRED MCP Server + Space RPG (space-rpg-h5) + KASKAD / Phantom Brigade Mod
> 每一条都违反过。所以记下来。

---

## 一、AI 输出可靠性铁律

### 1. 永远不信任 AI 返回的 JSON

**问题：** AI 会在 JSON 外包裹自然语言解释、改字段名、编造不存在的键。

**防御：** 严格 prompt 约束 + 后解析校验 + 降级兜底，三层防御。

```
┌─ 第一层：prompt 中明确定义 JSON schema
├─ 第二层：解析后用 JSON Schema validator 校验
└─ 第三层：校验失败回退到手动提取或用默认值
```

**本项目的实践：** MCP 工具返回的都是 Python dict（由 FastMCP 框架序列化），不依赖 AI 生成 JSON。

### 2. AI 过度设计是常态

**问题：** AI 会给你设计 APIKeyManager 类、RequestQueue 类、ConnectionManager 类——实际场景可能只需要 3 个函数。

**防御：** 学会对 AI 方案说"太多了，砍掉"。

**本项目的实践：** server.py 397 行、loader.py 194 行，两个文件解决所有跑团工具需求。没有引入任何不必要的抽象层。

### 3. AI 生成的数值不可直接作为最终配置

**问题：** AI 给出的百分比、倍率等量化评估，可能看着合理但未经实测。

**防御：** AI 生成的数值用于方案讨论和方向判断，标注【待验证】。正式数值需用户确认或实测校准。

**本项目的实践：** 486 条规则数据全部来自规则书 PDF 的结构化提取，MCP 只做查询和呈现，不自行推导数值。

### 4. AI 代码审查容易陷入代码美学

**问题：** 打了 4/5 分的代码可能有三处 HTML→JS 接口断裂导致基本功能不可用。

**防御：** 代码审查必须补充端到端链路检查，不只审代码本身。

**本项目的实践：** 41/41 烟雾测试覆盖了从工具调用到结果验证的完整链路，不是单元测试。

## 二、工程管理铁律

### 5. 第一天就用配置对象

不要指望"后面再清理硬编码"。后面通常不会清理。80 个散落数值就是代价。

### 6. 跨文件命名必须统一

camelCase 或 PascalCase 选一个贯彻到底。`apiManagerInstance` vs `APIManagerInstance` 这种事不该发生。

### 7. 占位符必须标记 TODO

功能看起来完成了，实际上全是断裂的。占位符标记 TODO，集成时逐一验证桥接。

### 8. 同一配置集中定义

散落在不同文件中，必然导致不一致。本项目用 `source_config.json` 集中管理所有数据源的启用状态和优先级。

### 9. Mock 数据必须标记

集成时逐一清除。否则"开发时能跑，上线后发现全是假数据"。

### 10. 所有网络请求必须有超时+重试+用户可中断

原生 fetch 没超时，页面卡死用户骂娘。MCP 虽不走 HTTP，但 loader.py 的文件 I/O 在启动时一次性完成，运行时零外部依赖。

### 11. 端到端链路检查不可省

代码审查、单元测试都通过了，但用户点按钮没反应——因为 HTML→JS 接口名写错了。MCP 同理：工具注册了但实际调用路径断裂，只有端到端测试能发现。

## 三、项目管理铁律

### 12. 先验证 API/SDK 能力边界，再写生产代码

22 个虚构 API 调用的 FlightSystem.cs 是血的教训。

**本项目的实践：** MCP 工具设计前先确认 FastMCP 3.x 能做什么、不能做什么；确认 MCP 协议本身没有"只读"强制能力后，改用三层防御替代。

### 13. 正确顺序：能力边界 → 框架 → 概念 → 生产

不能跳步。本项目走了：
1. PDF 提取能力验证
2. 规则结构化框架确认（7 分类、三层模型）
3. GM 路由节点设计（N0-N10）
4. MCP Server 实现

### 14. 估算先于执行

无估算 = 成本失控风险。自底向上估算，精度 ±20%。本项目每个 Phase 有明确的范围和验收标准。

### 15. 子代理 ≠ 万能

3 个并行子代理 = token 黑洞。本地扫描（read_file/search_content/list_dir）优先。

### 16. 动手前先看市面上有没有现成方案

七天造了个完整的轮子，发现 SillyTavern 已经做完了更圆的——不是失败，但下次先调研再动手。

## 四、本项目的额外铁律

### 17. 真实样本是最好的老师

理论讨论可以吵好几天，鲨鱼包 136 个文件扔进来五分钟就能看到"一键导入"假设全面崩溃。

### 18. 测试资产不可丢弃

第一次 41 用例由 Claude 跑完顺手删了，现在固化在 TEST_CHECKLIST.md。**测试是永久资产，不是一次性消耗品。**

### 19. 设计文档比代码长寿

v2 代码被 v3 重构了，但 v2 的 22 项设计决策仍然锁定在 PROJECT.md 里，作为架构演进的可追溯记录。

### 20. MCP 通过 stdio 实际调用验证，禁止直接函数调用测试

MCP 协议的价值在跨进程通信。直接 import server.py 调用函数测试，测不出 MCP 集成问题。
