# Cyberpunk RED MCP Server — 使用说明书 v2

> 赛博朋克 RED AI 单人跑团引擎 · 配合叙事引擎系统使用
> 更新日期：2026-05-05 · 基于神谕+时钟+随机表全部定案

---

## 一、概述

Cyberpunk RED MCP Server 是本地 stdio 型 MCP 服务，为 WorkBuddy 提供三个核心能力：规则查询、骰子判定、随机表生成。它是叙事引擎的数据层。

### 数据规模

| 数据 | 数量 | 说明 |
|------|:----:|------|
| 规则条目 | **486 条** | 7 个分类：injuries / combat / vehicles / netrunner / skills / services / equipment |
| 随机表 | **39 张** | 含神谕（5级概率）+ 士气（5种敌人）+ 动词/名词/形容词等 |
| 工具 | **7 个** | 3 跑团 + 3 数据管理 + 1 预处理 |

### 工具一览

| 工具 | 类型 | 用途 |
|------|------|------|
| `roll` | 跑团 | 掷骰子（d10, 2d6, 6d6, d100 等） |
| `search_rules` | 跑团 | 搜索 486 条规则（全字段子串匹配） |
| `roll_table` | 跑团 | 查 39 张随机表 + 神谕 5 档 + 士气 5 档 |
| `list_sources` | 管理 | 查看数据源层级和状态 |
| `set_source_priority` | 管理 | 调整第三方扩展优先级 |
| `import_extension` | 管理 | 导入经审核的第三方扩展包 |
| `prepare_extension` | 预处理 | 预提取第三方文档（PDF/Word/Excel/CSV/MD） |

## 二、快速上手

### 2.1 前提条件

- WorkBuddy 中 cyberpunk-red MCP Server 已在 MCP 设置中"信任"
- 数据文件位于 `mcp_server/data/`，启动时自动加载
- 39 张随机表（v2 新增名词表、形容词表）

### 2.2 工具在叙事引擎中的角色

三个跑团工具对应叙事引擎的三个子系统：

```
roll_table(神谕)  →  神谕引擎（不确定性生成）
roll(6d6)        →  强者时钟（压力管理 / 骰池衰减）
roll_table(随机表) →  随机表（细节填充 / O-08 非二元结果锚定）
search_rules     →  规则判定（DV / SP / 伤害 / 赛博组件）
```

### 2.3 你的第一个跑团回合

```
玩家："我朝那个帮派成员开枪！"（重型手枪，技能+7）

→ roll("1d10+7")                → total=10 vs DV13 → 未命中
→ search_rules("重型手枪")      → 伤害 3d6
→ roll("3d6")                   → [4,5,2]=11 伤害
→ search_rules("护甲", "combat") → SP7 规则
→ roll_table("神谕 50/50")      → "否但" → 帮派成员受伤但没跑
```

## 三、七大工具详解

---

### 3.1 `roll` — 掷骰子

赛博朋克 RED 的核心判定工具。D10 + 技能值 + 属性 ≥ DV。

**参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `expression` | string | ✅ | 骰子表达式 |

**支持的表达式**

| 格式 | 示例 | 用途 |
|------|------|------|
| `dN` | `d10` | 技能判定 |
| `NdN` | `2d6`, `3d10`, `6d6` | 伤害/时钟骰池 |
| `NdN+M` | `1d10+7` | 带修正的判定 |
| `d%` | `d%` | 百分骰 |

**返回值**

```json
{"expression":"1d10+7", "rolls":[3], "modifier":7, "total":10}
```

**叙事引擎中的关键用法**

```
# 技能判定
roll("1d10+7")           → 手枪判定 = 1d10+REF+技能

# 伤害骰
roll("3d6")               → 重型手枪 3d6

# 时钟骰池（核心）
roll("6d6")               → 全池掷出，移除所有结果为1的 → 骰池缩小

# Luck 烧点
roll("2d6")               → 玩家烧1点Luck → 掷2d6 → 在原d100上±2d6
```

### 3.2 `search_rules` — 搜索规则

486 条结构化规则的全字段子串匹配。支持 7 个分类过滤。

**参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `query` | string | ✅ | 搜索关键词（越短匹配越多） |
| `category` | string | ❌ | 限定分类，不填=全局 |

**7 个分类**

| 分类 | 条目数 | 内容 |
|------|:-----:|------|
| `injuries` | 26 | 重要伤势、致命伤规则 |
| `combat` | 85 | 战斗动作、远程/近战、护甲、闪避 |
| `vehicles` | 14 | 载具战、载具属性 |
| `netrunner` | 54 | 网行程序、黑冰、交互界面 |
| `skills` | 66 | 66项技能完整参考 |
| `services` | 98 | 医疗、生活风格、遭续表、FAQ |
| `equipment` | 140 | 武器/护甲/弹药/赛博组件 |

**返回值**

```json
{
  "query": "重型手枪",
  "category": "equipment",
  "total_matches": 1,
  "results": [{
    "source": "equipment",
    "match_field": "武器种类",
    "record": {"武器种类":"重型手枪","单发伤害":"3d6","弹容":"8发","ROF":2,"价格":"100 eb"}
  }]
}
```

**匹配优先级**：精确匹配 > 开头匹配 > 包含匹配。最多返回 10 条。

**使用示例**

```
search_rules("闪避", "combat")      → 远程闪避规则 + DV表
search_rules("致命伤", "injuries")  → 致命伤触发条件和死亡豁免
search_rules("SP", "equipment")     → 全部护甲条目
search_rules("治疗")                 → 全局搜索，多个分类返回
```

### 3.3 `roll_table` — 随机表

叙事引擎的核心。39 张标准表 + 神谕 5 档 + 士气 5 种。

**参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `table_name` | string | ✅ | 表名（模糊匹配） |
| `roll_value` | integer | ❌ | 手动指定骰值（O-16偏移用，不填则自动掷） |

**返回值**

```json
{
  "table_name": "名词",
  "dice": "1d100",
  "roll": 48,
  "result": "手雷",
  "result_index": 47,
  "result_min": 48,
  "result_max": 48,
  "type": "simple",
  "source": "core",
  "table_version": "1.0"
}
```

#### 3.3.2 神谕（Oracle）

单人跑团的 GM 替代品。5 个概率等级对应 d100 的 5 个结果区间。

| 等级 | 否 | 否但 | 复杂化 | 是但 | 是 |
|------|:---:|:---:|:---:|:---:|:---:|
| `必然` | 1-5 | 6-10 | 11-15 | 16-40 | 41-100 |
| `很可能` | 1-15 | 16-25 | 26-35 | 36-55 | 56-100 |
| `50/50` | 1-20 | 21-30 | 31-40 | 41-60 | 61-100 |
| `不太可能` | 1-40 | 41-55 | 56-65 | 66-75 | 76-100 |
| `不可能` | 1-75 | 76-85 | 86-90 | 91-95 | 96-100 |

**使用方式**

```
roll_table("神谕 50/50")   → 基础用法
roll_table("神谕 很可能")  → 高概率事件
roll_table("神谕 必然", roll_value=3) → 极端反转（O-15触发时钟）
```

**叙事引擎中的处理路径**

| 结果 | 处理 |
|------|------|
| 肯定/否定 | 直接叙事 |
| 否但/是但/复杂化 | O-08 按场景类型查随机表（1张或3张），AI缝合 |
| 极端翻转（必然1-5否 / 不可能96-100是） | O-15 触发时钟判定 |
| 与事实矛盾 | O-11 判真假 → 真矛盾触发时钟 |

### 3.4 `list_sources` — 查看数据源

无参数。返回已加载的全部数据源及其优先级。

```json
{
  "sources": [
    {"name":"core","priority":0,"enabled":true,"rules_count":486,"tables_count":39}
  ],
  "total_rules": 486,
  "total_tables": 39
}
```

---

### 3.5 `set_source_priority` — 管理扩展优先级

| 参数 | 类型 | 说明 |
|------|------|------|
| `source_name` | string | 源标识 |
| `enabled` | boolean | 启用/禁用 |
| `priority` | integer | 优先级（越大越优先，core固定0） |

---

### 3.6 `import_extension` — 导入扩展

导入链路的终端。先用 `prepare_extension` 预处理。

| 参数 | 类型 | 说明 |
|------|------|------|
| `source_name` | string | 扩展包标识 |
| `data_type` | string | `"rules"` 或 `"tables"` |
| `file_path` | string | 已审核的 JSON 路径 |
| `mode` | string | `"extend"` 或 `"override"` |

---

### 3.7 `prepare_extension` — 预处理文档

提取第三方文档（PDF/Word/Excel/CSV/MD）的结构化摘要。不做导入决策。

**流程**：`prepare_extension` → AI引导映射 → 人工审核 → `import_extension`

## 四、叙事引擎场景

### 场景 1：O-08 非二元结果处理

```
# 神谕出"是但"
roll_table("神谕 50/50")
→ roll=42 → "是但"（肯定，但有并发症）

# O-08：按场景类型查表。社交场景 → 情绪表
roll_table("情绪")
→ roll=77 → "悲怆"

# AI缝合：
# "NPC配合了，但神情悲怆——他正在失去什么。"
```

### 场景 2：O-15 极端反转 + 时钟

```
# 必然档出否定
roll_table("神谕 必然", roll_value=3)
→ roll=3 → "否" ⚠️ 极端反转

# O-15：触发时钟判定
roll("6d6")
→ [4,1,4,3,3,6] → 移除1 → 骰池 [4,4,3,3,6]

# AI叙事：只声明矛盾
# "这个仓库应该有安保轮班。此刻走廊里没有脚步声。这不寻常。"
```

### 场景 3：O-16 偏移系统（GM修正）

```
# 原始神谕出"敌对者"
roll_table("关系")
→ roll=90 → "敌对者" (result_index=89)

# GM想修正为"挚友"（表中 index=14）
# 偏移量 = |14-89| = 75 → 封顶 5 → 5 级麻烦

# 注入 5 个等量麻烦：额外前置任务、NPC反水风险、时间压力...
```

### 场景 4：完整战斗回合

```
# 攻击判定
roll("1d10+7")                    → 技能判定

# 伤害
roll("3d6")                        → 武器伤害

# 护甲
search_rules("护甲", "combat")     → SP 规则

# 严重伤势（出双6时）
search_rules("严重伤势", "injuries") → 伤势表

# 士气
roll_table("士气")                → 敌人是否逃跑
```

### 场景 5：剧本构建（阶段一）

```
# 任务框架
roll_table("任务类型")             → "窃取原型机"
roll_table("企业名录_笔记")        → "戴顿航空"
roll_table("区域")                → "滨海区上段"
roll_table("访客")                → "归乡游子"
roll_table("情绪")                → "奋进"
roll_table("关系")                → "父母"

# 不满意？O-16 偏移修正 → 行距 → 麻烦注入
```

## 五、数据源架构

```
┌─────────────────────────────┐
│  extensions/ (第三方)       │  ← import_extension 导入，优先级最高
├─────────────────────────────┤
│  core/                      │  ← 核心规则书，优先级固定 0
│  rules/*.json (7个分类)     │     486 条规则，不可修改
│  random_tables/cyber.json   │     39 张随机表
│  random_tables/table_index  │     表索引
└─────────────────────────────┘
```

**原则**：core 不可改、扩展独立存储、表行序锁定（偏移量引用保护）。

## 六、与叙事引擎的接口映射

| 引擎规则 | MCP 调用 |
|---------|---------|
| O-06 笔记有答案？ | AI 判断，不调 MCP |
| O-09 玩家有动作？ | AI 判断，"是"→roll("1d10+技能")，"否"→roll_table("神谕") |
| O-07 B型安保等级映射 | AI 根据剧本查概率档 |
| O-08 非二元查表 | roll_table("名词"/"情绪"/"动词") |
| O-15 极端反转 | roll_table("神谕 必然", roll_value=3) → roll("6d6") |
| O-11 事实矛盾 | 同上，触发时钟 roll("Nd6") |
| O-14 烧 Luck | roll("2d6") → 手动计算区间 |
| O-16 偏移 | roll_table("表名", roll_value=目标) → 计算行距 |
